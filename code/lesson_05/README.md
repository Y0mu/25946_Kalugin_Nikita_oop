# Занятие 5. CMake, библиотека, GoogleTest

Материалы: `lesson/OOP_05.pdf`, задания: `tasks/Задания OOP_05.txt`.

Задания идут по цепочке: каждое следующее — это доработанная версия предыдущего.
Поэтому здесь пять отдельных проектов (папок), чтобы было видно, что именно менялось.

| Папка | Задание | Что добавлено |
|---|---|---|
| `task_05_1_cmake_basic/` | 5.I | CMake, статическая библиотека в одной папке с `main.cpp` |
| `task_05_2_cmake_subdir/` | 5.II | библиотека переехала в поддиректорию `my_lib/`, появился `add_subdirectory` |
| `task_05_3_gtest/` | 5.III | подключён GoogleTest, тесты в директории `tests/` |
| `task_05_4_build_option/` | 5.IV | опция `BUILD_TESTS`, которой тесты включаются и выключаются |
| `task_05_5_templates/` | 5.V | функции библиотеки стали шаблонными, заголовки вынесены в `include/` |

В каждой папке лежит `build.txt` с точными командами сборки и запуска.

## Важно: только командная строка

По условию задания проект нельзя создавать средствами IDE и нельзя запускать
сборку из IDE. Все команды — в терминале:

```
cmake -S . -B build
cmake --build build
```

## Про GoogleTest

В заданиях 5.III–5.V GoogleTest подключается через `FetchContent` —
CMake сам скачивает нужную версию при конфигурации. Нужен доступ в интернет
при первой сборке. Если интернета нет, в `tests/CMakeLists.txt` можно заменить
блок `FetchContent` на `find_package(GTest CONFIG REQUIRED)` (подробности в `build.txt`).

## Три способа запустить тесты (из лекции)

1. `./build/tests/my_tests` — запустить исполняемый файл с тестами напрямую;
2. `ctest` из директории сборки;
3. `ctest --output-on-failure` — то же самое, но с выводом подробностей по упавшим тестам.

## Разница ASSERT_ и EXPECT_

* `EXPECT_*` — некритическая проверка: тест продолжается, и видно сразу все ошибки;
* `ASSERT_*` — критическая проверка: тест обрывается на первой же ошибке.

В каждом наборе тестов есть два «провальных» теста с приставкой `DISABLED_`.
Убираем приставку — и видно эту разницу на практике.
